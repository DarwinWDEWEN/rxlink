# 控制台中文化设计（构建期字面量替换）

> 状态：**设计已批准，待实施**（2026-11-13）。
> 范围：只翻译**界面文案**（295 条），**不翻**国家名 / 浏览器名 / OS 名等数据值。
> 决策已获用户批准：做；只翻界面。

---

## 1. 背景与目标

`console.example.com` 的控制台是 shlink 上游 `shlink-web-client` v4.9.0（React 应用）。
上游**没有任何 i18n 基础设施**：无 i18n 库、无 `Trans` 组件、无 locale 管道，
字符串全部以 JS 字面量硬编码在构建产物里。上游 issue `shlinkio/shlink-web-client#31`
状态 `wontfix`（2018-11-02），所以只能由我们自己做。

**目标**：让控制台界面显示中文，且不引入运行时开销、不 fork 上游源码。

---

## 2. 现状（实测）

| 层 | 位置 | UI 文案量 |
|---|---|---|
| 我们自己的代码 | `shlink-web-client/src`（2397 行） | 8 条 |
| 上游组件库 | `@shlinkio/shlink-web-component` v0.20.0 | 260 条 |
| 上游共享组件 | `@shlinkio/shlink-frontend-kit` v1.6.1 | 49 条 |
| **合计（去重）** | | **295 条 / 407 处出现** |

另有 **262 条数据值**（242 个国家名 + 浏览器/OS 名）**不在本次范围内**。

**三个关键事实**（决定了方案可行性）：

1. **产物未压缩**，且保留 `//#region src/...` 源文件路径标记（共 10 个，覆盖不全，仅供人工核对）。
2. **字符串全是 JS 字面量**（`"..."`），可精确匹配与计数。
3. **两个上游包都不用 shadow DOM**（`shlink-web-component` 已从 Lit 迁到 React），
   渲染到 light DOM —— 运行时方案在技术上可行，但构建期方案更稳。

文案出现次数分布：242 条出现 1 次，53 条多处出现（`Saving...` 4 次、`DESC` 跨 3 个 bundle 5 次）。

> 注：295 条是**自动提取的候选数**，其中混有逻辑 key（见 §6）。人工审核后的字典条目会**少于 295**，
> 以审核后的 `zh-CN.json` 为准。

---

## 3. 方案

### 3.1 选型

| 方案 | 结论 |
|---|---|
| **构建期字面量替换** ✅ | **采用**。零 fork、零运行时开销、可断言 |
| 运行时 DOM 翻译 | 否决：英文闪烁、动态拼接文案译不了、性能开销、更脆 |
| fork 上游源码做原生 i18n | 否决：从此维护两个包的源码与构建链，成本最高 |

### 3.2 架构

```
构建期：
  源码（上游 dist/*.js + src/**）
    → Vite transform（i18n 插件按字典替换字面量）
    → 产物（中文）
    → build-console-fc.mjs → dist/console.zip → 上传 FC
```

运行时**无变化**：产物是纯静态的中文 JS，浏览器照常加载。

### 3.3 文件清单

| 文件 | 作用 |
|---|---|
| `scripts/i18n/zh-CN.json` | 字典：`{ "English": "中文" }`，经人工审核后的最终条目（初始候选 295 条） |
| `scripts/i18n/expected.json` | 断言基准：`{ "English": <全局预期出现次数> }`（初始候选合计 407 处） |
| `scripts/i18n/vite-plugin-i18n.mjs` | vite 插件：替换 + 计数 + buildEnd 校验 |
| `scripts/i18n/test/vite-plugin-i18n.test.mjs` | 插件单测 |
| `vite.config.ts`（改） | 引入插件 |
| `package.json`（改） | 加 `build:en` 脚本 |
| `shlink-web-client/src/**`（改） | 8 条硬编码文案走同一字典 |

## 4. 插件设计

### 4.1 行为

1. **transform 阶段**处理两类模块：
   - `node_modules/@shlinkio/**/dist/*.js`（上游产物）
   - `src/**/*.{ts,tsx}`（我们自己的代码）
2. 对每个模块，遍历字典，把 `"English"` 字面量替换为 `"中文"`。
   - 中文字面量用 `JSON.stringify(zh)` 生成，正确处理引号与特殊字符。
   - 只替换**完整字面量**（`"English"` 精确匹配），不做子串替换。
3. 累计每条文案的替换次数。
4. **buildEnd 阶段**校验：每条字典文案的实际替换次数 == `expected.json` 的预期值。
   - 不符 → **抛出错误，构建失败**。
5. 字典里没有的文案 → 保留英文（回退，不报错）。

### 4.2 断言机制（本方案的核心价值）

上游升级后如果改了某条文案（增/删/改字），断言会失败，**避免静默漏翻**。
错误信息需包含：文案原文、预期次数、实际次数、所在模块。

### 4.3 环境变量

- `I18N_LANG=zh-CN`（默认）→ 启用替换
- `I18N_LANG=en` → 不启用（构建英文原版，回退用）

---

## 5. 语言形态

- `npm run build` → 中文产物（默认）
- `npm run build:en` → 英文产物（原始，回退用）
- **不做运行时切换**（YAGNI）。要英文就 `build:en` 重新构建部署。

理由：这是自用/内部平台，中文优先；运行时切换需要双产物 + 语言选择器 + 存储，
收益低于成本。若将来需要，可在本方案基础上加运行时层。

---

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| **逻辑 key 误伤**：抓出的 295 条里混着 `ASC`/`DESC`/`ArrowUp`/`Card.Body` 这类代码 key | 字典**人工审核**，只保留真正显示给用户的文案；剔除全部逻辑 key |
| **模板字符串**：`` `text ${x}` `` 形式正则抓不到 | 实施时扫描上游产物确认；若有则单独处理（正则扩展或人工条目） |
| **上游升级导致文案变化** | 构建断言失败 → 更新字典（这是特性，不是 bug） |
| **误替换非 UI 字符串** | 只替换字典内的精确字面量；字典经人工审核 |
| **中文文案里的引号/特殊字符** | 用 `JSON.stringify` 生成字面量 |
| **翻译质量** | 用户验收（中文母语者，熟悉 shlink 术语口径） |

## 7. 测试策略

| 层级 | 内容 |
|---|---|
| 插件单测 | 替换正确性、计数准确性、断言失败路径、`en` 模式不替换 |
| 构建断言 | `npm run build` 时字典**全部条目**命中预期次数（初始候选 295 条 / 407 处） |
| 端到端 | Playwright 截图 3–5 个页面（短链列表 / 创建 / 设置 / 访问统计）确认中文 |
| 回归 | 兼容层 117 例不受影响（不涉及） |

---

## 8. 验收标准

1. `npm run build` exit 0，字典全部条目断言全过（初始候选 295 条 / 407 处，审核后条数以下降为准）。
2. `npm run build:en` exit 0，产物与改动前一致（英文）。
3. Playwright 截图确认关键页面显示中文。
4. 控制台功能不受影响（列表 / 创建 / 编辑 / 设置 / 统计可用）。
5. 兼容层 117 例仍全绿。

---

## 9. 明确不做

- 不翻国家名 / 浏览器名 / OS 名（262 条数据值）。
- 不做运行时语言切换。
- 不 fork 上游源码。
- 不改上游包的版本。
- 不动 `docs/manual/rxlink-manual.html` 的既有内容（中文手册继续保留，作为补充）。
