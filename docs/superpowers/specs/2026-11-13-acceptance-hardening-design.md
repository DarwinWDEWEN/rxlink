# rxlink 整体验收加固设计

## 目标

修复代码复查确认的四个验收阻塞问题，使项目具备可验证的 SSRF 防护、可观测的访问入队失败处理、可从空库重放的生产基线，以及真正生效的根仓库 CI 门禁。

## 范围

本轮包含：

- 标题自动解析的 DNS Rebinding 防护。
- 跳转函数访问入队的 HTTP 错误检查、有限重试和脱敏日志。
- Supabase 生产基线收口迁移与 seed 配置修复。
- 前端中英文行为、测试门禁、HTML 语言标记和根级 CI。

本轮不包含：

- 新建外部抓取代理服务。
- 改变短链跳转、统计口径或标题解析的产品语义。
- 自动操作 Supabase 套餐升级或 FC 控制台触发器。

## 设计

### 1. 标题抓取

`assertPublicHost` 在校验通过后返回解析地址。生产请求使用 Deno 的 `node:http` / `node:https` 兼容层发起，并通过自定义 `lookup` 只返回本轮已经校验的地址。这样 TCP 连接不能再次解析到其他地址，TLS 仍使用原始域名完成 SNI 和证书校验。

每次 HTTP 重定向都重新解析、检查并固定目标地址。请求继续维持手动重定向、总超时、响应体上限、协议限制、凭据 URL 拒绝和脱敏日志。测试注入接口必须能断言请求器收到的地址与校验结果一致。

### 2. 访问入队

`recordVisit` 检查每次响应的 `ok` 状态。HTTP 4xx/5xx 与网络异常使用同一套有限重试，超过次数后输出不含 URL、IP、UA、Referer 和密钥的错误日志。访问统计失败不改变用户跳转响应。

测试覆盖首次 500 后恢复、持续 500 最终记录错误、正常 201 不重试。

### 3. 数据库基线

新增 `0021_production_baseline.sql`，完成以下幂等收口：

- 删除 P0 阶段的 `probe_*` 函数、表和相关任务。
- 将 id=0 且仍为占位值的默认域名更新为 `example.com` 和 `https`。
- 以“同名任务先取消再创建”的方式固化 `rxlink-drain`、`rxlink-prune`、`rxlink-retire-ip` 和 `rxlink-expired`。

`supabase/config.toml` 关闭当前不存在的 seed。CI 使用 Supabase 本地环境执行空库重放，并断言探针对象不存在、默认域名正确、四个任务齐全。

### 4. 前端与 CI

国际化 Vite 插件只在 production build 阶段执行，Vitest 继续验证源码英文行为。编辑服务器标题改为带命名占位符的完整字面量，中文词典整体替换为中文引号，英文构建保持成对直引号。

插件在中文构建时将 HTML 根节点语言改为 `zh-CN`，英文构建保持 `en`。构建验证同时检查语言标记和中英文产物。

根目录新增 GitHub Actions workflow，覆盖：

- 云函数和国际化脚本测试。
- Deno 兼容层测试与类型检查。
- 前端规范、类型、完整测试、中文构建和英文构建。
- Supabase 空库迁移重放与生产基线断言。

发布流程必须依赖上述门禁通过后才能生成产物。

## 错误处理

- 标题抓取的 DNS、连接、证书、超时和内容错误继续降级为“无标题”，不阻断建链。
- SSRF 校验失败必须 fail closed。
- 访问入队最终失败只记录脱敏原因，不向最终用户暴露内部状态。
- 迁移和 CI 任一断言失败都以非零状态退出。

## 测试与验收

所有行为修复遵循红、绿、重构：

1. 先新增能稳定复现问题的失败测试。
2. 只实现让该测试通过的最小改动。
3. 运行相邻套件，确认无回归。
4. 最后运行全量门禁、部署包构建和线上只读冒烟。

完成标准：

- 前端 `237/237` 通过，默认中文与英文模式均无行为回归。
- 云函数、国际化脚本和 Deno 兼容层全部通过。
- DNS 固定测试证明连接地址只能来自已校验结果。
- 访问入队 500 不再静默。
- 空库重放后无探针对象，默认域名与四个生产任务正确。
- 根仓库 CI 文件位于 `.github/workflows/`。
- 工作树只包含本轮预期改动。

## 外部验收项

以下仍需用户在云控制台完成，代码不能代替：

- Supabase 升级到允许生产使用的付费套餐。
- 确认 FC 定时触发器使用六字段 cron。
